## 4. 체결 규칙 (엔진이 지키는 순서)

신호는 **D일 장 마감 데이터**로 계산하고, 체결은 **D+1일**에 일어납니다. 미래 데이터는 쓸 수 없습니다.

### 4-1. 매수

| 주문 | 체결 방식 |
|---|---|
| `open` | D+1 **시가**로 체결 |
| `limit` | 지정가 = D일 종가 × (1 + `offset_pct`/100). D+1 저가가 지정가 이하면 체결. 시가가 이미 지정가보다 낮으면 시가로 체결. 못 닿으면 그날 주문 취소 |

- D+1 시가가 전일 종가 대비 +29.5% 이상(사실상 상한가)이면 매수하지 않습니다.
- 주문 수량은 **D+1 거래량의 5%**를 넘을 수 없습니다(넘는 만큼 잘림).
- 수량은 정수로 내림합니다. 현금이 부족하면 살 수 있는 만큼만 삽니다.
- 진입 후보가 여러 개면 `entry.rank` 순서대로, 하루 `max_new_per_day`개까지 삽니다. 순위가 같으면 거래대금 큰 종목이 먼저입니다.

### 4-2. 투자 금액 (sizing)

| 방식 | 1종목 투자 금액 |
|---|---|
| `all_in` (몰빵) | (현금 − 예비금) 전액. `max_positions`는 반드시 1 |
| `equal` (균등) | (현금 − 예비금) ÷ (남은 빈 자리 수) |
| `fixed_pct` (고정 비율) | 계좌 총자산 × `pct_per_position`% |

- 예비금 = 계좌 총자산 × `cash_reserve_pct`%. 이 돈은 매수에 쓰지 않습니다.
- 어떤 경우에도 한 종목 비중은 `max_weight_pct`%를 넘지 않습니다.
- 위 금액에 **분할매수 비율**(`split_buy[].pct`)을 곱한 만큼씩 나눠 삽니다.

### 4-3. 분할매수

- 1차(`entry`)는 진입 신호로 삽니다.
- 2차 이후는 D일 종가가 평균 매수가 대비 `drop_pct`(하락) 또는 `gain_pct`(상승) 값에 닿으면 D+1 시가에 삽니다.
- 첫 매수 후 `split_expire_days` 거래일이 지나면 남은 분할은 취소됩니다.

### 4-4. 매도

| 규칙 | 판정 | 체결 가격 |
|---|---|---|
| 익절 `take_profit` | 장중 고가 ≥ 평균매수가 × (1+`gain_pct`%) | 목표가. 시가가 이미 위면 시가 |
| 손절 `stop_loss_pct` | 장중 저가 ≤ 평균매수가 × (1+`stop_loss_pct`%) | 손절가. 시가가 이미 아래면 시가 |
| 트레일링 `trailing_stop_pct` | D일 종가가 보유 중 최고 종가보다 x% 이상 하락 | D+1 시가 |
| 기간 `max_hold_days` | D일 기준 보유 거래일 ≥ 값 | D+1 시가 |
| 신호 `signal_exit` | D일 조건 충족 | D+1 시가 (전량) |

- **같은 날 익절가와 손절가에 둘 다 닿으면 손절을 먼저 적용**합니다(보수적 처리).
- 익절·손절의 장중 판정은 시가 매수한 날부터, 지정가로 산 경우 다음 날부터 적용합니다.
- 익절이 여러 단계면 낮은 단계부터 `sell_pct`% (처음 보유 수량 기준)씩 팝니다.
- 하한가(전일 대비 −29.5% 이하 시가)에서는 매도가 체결되지 않고 다음 날 다시 시도합니다.
- 거래정지 종목은 체결하지 않고, 마지막 종가로 평가합니다.

### 4-5. 기타

- `reentry_cooldown_days`: 같은 종목을 판 뒤 이 거래일 수만큼 다시 사지 않습니다.
- `halt_if_drawdown_pct`: 계좌 최대낙폭이 이 값을 넘으면 신규 매수만 멈춥니다(보유분 매도 규칙은 그대로).
- 평가는 매일 종가 기준입니다.

## 7. 전략 파일 작성법

전략 1개 = JSON 파일 1개입니다. 양식은 `schema/strategy.schema.json`, 쓸 수 있는 지표는 `INDICATORS.md`에 있습니다.
예시 3개가 `examples/` 폴더에 있습니다 (몰빵 단타, 분할 눌림목, 고정비율 장기).

### 7-1. 필드 설명

| 필드 | 뜻 | 예 |
|---|---|---|
| `schema_version` | 항상 `"1.0"` | |
| `id` | `[팀]-[슬롯 2자리]_[버전]` | `GPT-03_0` |
| `team`, `slot`, `version` | ID와 똑같이 | `"GPT"`, `3`, `0` |
| `replaces` | 버전 0이면 `null`, 1 이상이면 대체하는 이전 기준 ID | `"GPT-03_0"` |
| `name` | 2~40자 이름 | `"거래량 폭발 추격"` |
| `philosophy` | 10~300자, 왜 이 전략이 통한다고 보는지 | |
| `submitted_at` | 제출 시각 (ISO 형식) | `"2026-10-12T20:00:00+09:00"` |
| `universe` | 어떤 종목 중에서 고를지 | 시장, 거래대금 하한, 가격·시총 범위, 조건 |
| `entry` | 언제 살지 | 조건, 순위 기준, 하루 최대 신규 종목 수 |
| `position` | 얼마나, 어떻게 살지 | 최대 종목 수, 몰빵/균등/고정비율, 주문 방식, 분할 |
| `exit` | 언제 팔지 | 익절 단계, 손절, 트레일링, 최대 보유일, 신호 청산 |
| `risk` | 위험 관리 | 예비 현금, 종목당 최대 비중, 재진입 대기, 매수 중단 낙폭 |

### 7-2. 조건 쓰는 법

조건은 `왼쪽 지표` · `연산자` · `오른쪽 값` 세 칸입니다.

```json
{"left": {"ind": "VOL_RATIO", "n": 20}, "op": ">=", "right": 3.0}
```
→ "오늘 거래량이 직전 20일 평균의 3배 이상"

```json
{"left": {"ind": "CLOSE"}, "op": "cross_above", "right": {"ind": "MA", "n": 20}}
```
→ "종가가 20일선을 아래에서 위로 뚫음" (어제는 아래, 오늘은 위)

```json
{"left": {"ind": "RSI", "n": 14}, "op": "between", "right": [25, 40]}
```
→ "RSI가 25 이상 40 이하"

| 연산자 | 뜻 |
|---|---|
| `>` `>=` `<` `<=` | 크다, 크거나 같다, 작다, 작거나 같다 |
| `==` | 같다 (실수에서는 거의 안 쓰임, 경고) |
| `cross_above` / `cross_below` | 어제→오늘 사이에 위로/아래로 교차 |
| `between` | `[최소, 최대]` 사이 (양끝 포함) |

`logic`이 `"all"`이면 모든 조건, `"any"`면 하나라도 맞으면 됩니다.
재무 지표(PER 등)가 비어 있는 종목은 그 조건을 **불충족**으로 처리합니다.

### 7-3. 검증기가 반려하는 경우 (최소 기준)

- 양식에 없는 필드, 목록에 없는 지표, 파라미터 범위 초과
- 청산 전용 지표(`POS_*`)를 진입·종목선별에 사용
- 손절·트레일링·최대보유일이 **모두 없는** 전략 (최소 1개 필수)
- 분할매수 비율 합계 ≠ 100, 익절 매도 비율 합계 > 100
- `all_in`인데 `max_positions` ≠ 1
- `fixed_pct` 비율 × 종목 수 > 투자 가능 비율
- ID·팀·슬롯·버전 불일치, 파일명·폴더 규칙 위반
- 거래대금 하한 10억원 미만

## 8. 기준 교체 규칙

1. 시작 시 팀마다 슬롯 01~10에 버전 `_0` 기준 10개를 냅니다.
2. 이후 새 기준(11번째)을 내면, 그 팀의 활성 기준 중 **누적수익률 최하위**가 정지됩니다.
3. 새 기준은 정지된 기준의 **슬롯 번호**를 이어받고 버전이 1 올라갑니다.
   예) `GPT-02_0` 최하위 → 정지, 새 기준은 `GPT-02_1` (`replaces: "GPT-02_0"`)
4. 운용 **20거래일 미만** 기준은 탈락 대상에서 빠집니다(다음 최하위가 대신 정지).
5. 신규 기준은 팀당 **주 1개**까지.
6. 정지된 기준은 다음 거래일 시가에 전량 청산하고, 기록은 영구 보존합니다.
7. 새 기준 요청 시에는 순위표로 정지될 슬롯을 먼저 확정해 AI에게 알려주고(부록 C), AI는 그 ID로 제출합니다.

## 9. 순위와 보고

- 기준 순위: 누적수익률 높은 순, 같으면 MDD 낮은 순
- 팀 순위: 활성 기준 10개 평균 누적수익률
- 매일 카카오톡: 팀 순위 3줄 + TOP 5 기준 + 교체·특이사항 + 대시보드 링크
- 모든 체결 내역은 `ledger/` 폴더에 기준별로 공개됩니다(엔진 단계에서 추가).

## 10. 제출 방법

1. AI가 전략 JSON을 출력합니다.
2. 존님이 `strategies/[팀]/[ID].json` 으로 저장해 GitHub에 올립니다
   (스마트폰: github.com/johnpark236-tech/vai-arena → strategies → 팀 폴더 → Add file → Create new file → 이름 `GPT-01_0.json` → 붙여넣기 → Commit).

# VAI 아레나 지표 목록 v1.0

전략 파일에는 아래 지표만 쓸 수 있습니다. 목록에 없는 지표는 검증기가 반려합니다.

- 모든 지표는 **당일 장 마감까지 확정된 데이터**로 계산하고, 주문은 **다음 거래일**에 체결됩니다.
- `_MA`, `_N` 계열 중 "직전 n일"이라고 적힌 지표는 **당일을 제외**합니다.
- 사용 위치: 종목선별=`universe.filters`, 진입=`entry.conditions`·`entry.rank`, 청산=`exit.signal_exit`
- 지표 참조 형식: `{"ind": "MA", "n": 20}` (파라미터는 같은 객체 안에 평평하게)
